Section 2
Data Preprocessing
Transforming raw messy data into a clean, numerical, ML-ready format while preserving business meaning.

🎯 Objective

Machine learning algorithms are mathematical operations — they cannot handle text, missing values, or features with wildly different scales. This section fixes all data quality issues: removes noise, imputes missing values with domain knowledge, encodes categories, and scales numerics so no single feature dominates training.

🔧 Preprocessing Pipeline
1
Drop Irrelevant & Leakage Columns
Remove Customer ID, location columns (Zip, Lat, Long, City), and critically — Churn Category and Churn Reason which only exist for customers who already churned (data leakage).
2
Create Binary Target Variable
Convert Customer Status (3 values: Stayed, Churned, Joined) into binary: Churned=1, Stayed/Joined=0. Joined customers are new and haven't had opportunity to churn.
3
Handle Missing Values
Domain-knowledge imputation: 'No Internet' for internet service columns, 'No Phone Service' for phone columns, 'No Offer' for offer column.
4
Encode Categorical Variables
Label Encoding for binary Yes/No columns, One-Hot Encoding for multi-class columns (Contract, Payment Method, Internet Type).
5
Feature Scaling
StandardScaler normalizes all numeric columns to mean=0, std=1 so large-range features like Total Revenue don't dominate distance-based algorithms.
💻 Key Code Explanations
🔹 df[col].fillna('No Internet') — Why not mean/mode?
What: Filling 1,526 missing values in internet-related columns.
Why 'No Internet' specifically: These values aren't missing randomly — they're missing BECAUSE those customers don't have internet service. Filling with the mode (e.g., "Fiber Optic") would falsely claim 1,526 customers have Fiber Optic service — completely wrong and would mislead the model.
This is called MNAR — Missing Not At Random. Always impute MNAR with domain-knowledge values, never statistical ones.
🔹 df['Multiple Lines'].fillna('No Phone Service')
Same logic: 682 customers without phone service can't have multiple lines. 'No Phone Service' is the factually correct fill value.
Three fill strategies used:
• Offer → 'No Offer' (no promotional offer was given)
• Internet cols → 'No Internet' (no internet subscription)
• Phone cols → 'No Phone Service' / 0 (no phone subscription)
🔹 df[numeric_cols] = scaler.fit_transform(df[numeric_cols])
What StandardScaler does: z = (x − mean) / std_deviation
After scaling: every numeric column has mean=0 and std=1.
Why it's needed: Before scaling, Total Revenue ranges $21–$8,684 while Age ranges 19–80. Without scaling, algorithms like Logistic Regression and KNN treat Total Revenue as 100× more important than Age — purely because of scale, not actual predictive power.
fit_transform(): fit() learns mean & std from data, transform() applies the formula. Combined into one step.
🔹 LabelEncoder vs get_dummies — When to use which?
LabelEncoder for binary columns (Yes/No → 0/1): Only 2 values, clean and compact.
get_dummies (One-Hot) for multi-class (Contract, Payment Method): Creates separate binary columns for each category.
drop_first=True: Avoids the dummy variable trap — if you know One Year=0 and Two Year=0, you automatically know it's Month-to-Month. Keeping all 3 creates perfect multicollinearity.

⚠️ Data Leakage Warning

Churn Category and Churn Reason were dropped because they only exist for customers who already churned. Using them would give the model information it wouldn't have when predicting future churn — like giving a student the answer sheet before the exam. This is called data leakage and produces artificially inflated metrics that collapse in production.

Section 4
Feature Selection
Identifying the top 15 most predictive features from 35+ using Recursive Feature Elimination.

🎯 Objective

After encoding, we have 35+ features. Not all are equally useful — some are redundant, some are noise, and some are genuinely predictive. We use RFE (Recursive Feature Elimination) to systematically identify the 15 features that contribute most to predicting churn, reducing overfitting and improving model efficiency.

❓ Why Feature Selection is Critical

❌ Without Feature Selection

→ Model trains on 35+ features
→ Learns noise and random patterns
→ Overfits — great on training, bad on test
→ Slower training
→ Harder to interpret results

✅ With Feature Selection (RFE)

→ Model trains on top 15 features only
→ Focuses on genuine churn signals
→ Better generalization to new customers
→ Faster, more efficient training
→ Clear, interpretable importance ranking

🔬 How RFE Works — Step by Step
1
Start with all 35+ features
Train Logistic Regression on all features. Rank each by absolute coefficient value — larger = more important.
2
Remove the weakest feature
The feature with the smallest absolute coefficient is eliminated. One feature removed per round (step=1).
3
Retrain & re-rank
Train a new model on the remaining features. Rankings can shift when a feature is removed.
4
Repeat until 15 remain
After ~20 rounds, only the top 15 most important features survive. These are used for all model training.
💻 Key Code Explanations
🔹 LogisticRegression(max_iter=1000, solver='lbfgs', random_state=42) as RFE estimator
Why Logistic Regression for RFE: It provides coefficients (weights) which RFE uses to rank importance. Fast, stable, and directly interpretable for binary classification.
max_iter=1000: Default is 100 — not enough for 35+ features to fully converge. We increase to 1000 to avoid ConvergenceWarning errors.
solver='lbfgs': The optimization algorithm. L-BFGS is the most efficient solver for small-to-medium binary classification datasets.
random_state=42: Fixed seed ensures the same 15 features are selected every run — reproducibility.
🔹 rfe.support_ and rfe.ranking_ — What they return
rfe.support_ → Boolean array: True = selected, False = eliminated
rfe.ranking_ → Integer array: 1 = selected (best), higher = eliminated earlier
Example: ranking = [1, 4, 1, 1, 7] — features at positions 0, 2, 3 are in top 15; feature at position 4 was eliminated 7th from the end (weak feature).
🔹 feature_ranks[...]['Feature'].tolist() — Why .tolist()?
.tolist() converts a pandas Series to a plain Python list. This is important because X[pandas_series] can sometimes produce warnings. X[python_list] is always clean and unambiguous for DataFrame column indexing.
🔹 .sort_values('Importance', ascending=True) — Why ascending for a top-features chart?
For plt.barh() (horizontal bar chart), matplotlib plots bars from BOTTOM to TOP. Sorting ascending=True (smallest first) means the most important feature ends up at the TOP of the chart where the eye looks first. Sorting descending would flip the chart upside-down.

Section 5
Model Building
Training and comparing 8 diverse machine learning algorithms to find the best churn predictor.

🎯 Objective

We train 8 fundamentally different algorithms on the same data to find which approach best predicts customer churn. Different algorithms make different assumptions about data — by testing diverse approaches, we ensure we find the optimal method rather than arbitrarily committing to one algorithm.

📐 Train-Test Split Strategy

80% Training → 5,634 customers — model learns patterns here
20% Testing → 1,409 customers — model is evaluated here
stratify=y → ensures BOTH sets have 26.5% churn rate
random_state=42 → same split every run (reproducibility)

⚠️ Why stratify=y is Critical

Without stratify, random splitting might put most churners in training and very few in test — making evaluation metrics unreliable. stratify=y guarantees both sets reflect the real 26.5% churn rate.

🤖 All 8 Models — How They Work & Why Included
📏
1. Logistic Regression
How it works: Draws a straight decision boundary. Uses the sigmoid function P(Churn) = 1/(1+e^−z) to convert a linear combination of features into a probability. If P > 0.5 → predict Churn=1.
✅ Baseline model — simplest possible approach. Highly interpretable. If complex models don't beat it, simpler is better.
👥
2. K-Nearest Neighbors (KNN)
How it works: For each new customer, finds the 5 most similar customers in training data. Majority vote among those 5 neighbors determines prediction. If 4 of 5 neighbors churned → predict Churn=1.
✅ Distance-based approach — no assumptions about data distribution. n_neighbors=5 is odd to avoid ties and is the standard starting point.
🌳
3. Decision Tree
How it works: Builds a flowchart of if/else rules. Example: IF Tenure < 12 AND Monthly Charge > $75 AND Contract = Month-to-Month → Predict Churn=1. Each split maximizes information gain.
✅ Most interpretable model — can be visualized as a tree. Typically overfits (high variance) which demonstrates why ensemble methods are needed.
🌲
4. Random Forest
How it works: Builds 100 different Decision Trees (n_estimators=100), each trained on a RANDOM subset of rows (bootstrap) and features. Final prediction = majority vote of all 100 trees.
✅ Ensemble bagging method — 100 trees voting reduces variance. Different random subsets mean trees make different errors which cancel out.
📈
5. Gradient Boosting 🏆 Best Model
How it works: Builds trees SEQUENTIALLY. Each new tree focuses on correcting the ERRORS of the previous tree. Tree 1: baseline. Tree 2: learns from Tree 1's mistakes. Tree 3: learns from Tree 2's mistakes. 100 iterations total.
✅ Sequential error correction is powerful for complex patterns. Our actual best model (65.56% F1). Key difference from Random Forest: sequential not parallel.
⚡
6. XGBoost 🥈 Runner-Up
How it works: Extreme Gradient Boosting — same sequential concept as Gradient Boosting but adds L1/L2 regularization, parallel processing, built-in missing value handling, and tree pruning. eval_metric='logloss' uses log loss for probability calibration.
✅ Industry gold standard for tabular data. Wins most Kaggle competitions with structured data. verbosity=0 suppresses internal logs.
📐
7. Support Vector Machine (SVM)
How it works: Finds the OPTIMAL hyperplane that maximizes the margin between churners and retained customers. Support Vectors are the data points closest to the boundary that define it.
✅ Works well in high-dimensional spaces. probability=True enables predict_proba() needed for ROC-AUC calculation — SVM doesn't natively output probabilities.
🎲
8. Naive Bayes
How it works: Uses Bayes' Theorem: P(Churn|features) = P(features|Churn) × P(Churn) / P(features). "Naive" = assumes all features are independent. GaussianNB assumes numeric features follow a normal distribution.
✅ Fastest model. Probabilistic approach contrasts all other models. Surprisingly competitive despite the naive independence assumption.

Section 6
Model Optimization
Fixing class imbalance with SMOTE and finding optimal hyperparameters with RandomizedSearchCV.

🎯 Objective

Two problems limit Section 5 performance: class imbalance (73.5% vs 26.5% biases all models) and default hyperparameters (models weren't tuned for our specific data). This section fixes both, optimizing the top 2 models to maximize F1-Score.

🧬 SMOTE — Synthetic Minority Over-sampling Technique
🔹 Why SMOTE instead of simple oversampling or undersampling?
Random Oversampling: Duplicates existing minority rows → model memorizes exact duplicates → overfitting
Random Undersampling: Deletes majority rows → loses valuable training data
SMOTE ✅: Creates SYNTHETIC new churners by interpolating between real ones — no duplication, no data loss

How SMOTE creates synthetic samples:
1. Pick a real churner (Customer A)
2. Find its K nearest neighbors (other real churners similar to A)
3. Randomly pick one neighbor (Customer B)
4. Create new synthetic customer anywhere on the LINE between A and B
5. New customer = A + random(0,1) × (B − A) → realistic but new!
🔹 smote = SMOTE(random_state=42) — What random_state does here
SMOTE uses randomness to decide which neighbor to interpolate toward. random_state=42 generates the exact same synthetic samples every run. Without it — different synthetic churners each time → inconsistent results.
🔹 X_train_sm, y_train_sm = smote.fit_resample(X_train, y_train)
fit() → SMOTE analyzes minority class geometry, finds nearest neighbors
resample() → generates synthetic churners until classes are balanced
Result: Training set goes from 73.5/26.5 → 50/50
Critical: SMOTE applied to X_train ONLY — test set stays at real 26.5% distribution for honest evaluation.
⚙️ RandomizedSearchCV — Hyperparameter Optimization
🔹 What are hyperparameters and why do they matter?
Model parameters (learned automatically): feature weights, split thresholds
Hyperparameters (set by YOU before training): n_estimators, learning_rate, max_depth
Default hyperparameters are generic — they don't know your specific data. Tuning finds the combination that maximizes performance on YOUR dataset.
🔹 RandomizedSearchCV vs GridSearchCV
GridSearchCV: Tests EVERY combination — 4×4×4×4×3×3 = 2,304 combinations. Too slow.
RandomizedSearchCV ✅: Tests only n_iter=50 RANDOM combinations. Research shows random search finds near-optimal results in far fewer iterations. ~97% faster than grid search.
🔹 Every hyperparameter in gb_param_grid explained
n_estimators [100,200,300,500] → how many trees. More = better learning but slower + diminishing returns
max_depth [3,4,5,6] → tree depth. Shallow=underfit, deep=overfit. Boosting works best with shallow trees (3-5)
learning_rate [0.01,0.05,0.1,0.2] → how much each tree contributes. Low=precise but needs more trees. Inverse relationship with n_estimators
subsample [0.7,0.8,0.9,1.0] → fraction of rows per tree. Adds randomness → reduces overfitting
min_samples_split [2,5,10] → min samples to split a node. Higher = more conservative = regularization
max_features ['sqrt','log2',None] → features considered per split. Restricting adds randomness → less overfitting
🔹 cv=5 — What 5-fold cross-validation means
Splits training data into 5 equal parts. Trains on 4 folds, validates on 1. Repeats 5 times. Averages the 5 F1 scores. This means for 50 iterations × 5 folds = 250 total model fits. Much more reliable than a single train-val split which could be lucky or unlucky.
🔹 n_jobs=-1 — What this does
Uses ALL available CPU cores in parallel. -1 = use every core. The 250 model fits are distributed across all cores simultaneously. Without this, runs on 1 core — potentially 4-8× slower depending on the machine.
🔹 gb_before = results_df[results_df['Model'] == 'Gradient Boosting'].iloc[0]
Retrieves pre-optimization scores dynamically from results_df. results_df['Model'] == 'Gradient Boosting' creates a boolean filter. .iloc[0] gets the matching row as a Series. This ensures we compare against exact Section 5 scores — not hardcoded numbers that could be wrong.
🔹 for ax, metric in zip(axes, metrics_to_plot)
zip() pairs each subplot axis with its metric name: (ax1,'Accuracy'), (ax2,'F1-Score'), (ax3,'ROC-AUC'). Each loop iteration draws one subplot. Without zip, you'd need to repeat identical bar chart code 3 times — one per metric. Elegant and concise.

💰 Business Cost Analysis

False Negative cost: ~$75/month × 12 months = ~$900/year per missed churner
False Positive cost: ~$20 retention offer = minor cost
This is why Recall is the most important metric — we'd rather flag 10 false alarms than miss 1 real churner.

💻 Key Code Explanations
🔹 precision_recall_curve(y_test, final_y_prob)
Computes precision and recall at EVERY possible probability threshold — not just 0.5.
Returns: precision_vals, recall_vals, thresholds arrays.
Why it matters: The default threshold of 0.5 isn't always optimal. For churn, lowering to 0.35 might increase Recall (catch more churners) at the cost of Precision (more false alarms). This trade-off is quantified by the curve.
🔹 The Precision-Recall Trade-off Explained
Lower threshold (e.g., 0.3): More customers flagged as churners → Recall↑ (catch more) but Precision↓ (more false alarms)
Higher threshold (e.g., 0.7): Fewer customers flagged → Precision↑ (more confident) but Recall↓ (miss more churners)
For churn: We prefer lower thresholds — catching a churner saves $900/year, a false alarm wastes $20. The asymmetric cost justifies accepting more false alarms.
🔹 roc_curve and roc_auc_score — What AUC really means
ROC Curve plots True Positive Rate vs False Positive Rate at every threshold. AUC (Area Under Curve) summarizes the full curve in one number.
Intuitive meaning: AUC = 0.89 means "if you randomly pick one churner and one retained customer, the model correctly ranks the churner as higher risk 89% of the time."
AUC is threshold-independent — it measures fundamental discrimination power regardless of where you set the decision boundary.
🔹 gb_base_model = models['Gradient Boosting'] — Why this still works
ML model objects in Python are stateful. After .fit(), the model stores all learned parameters internally. models['Gradient Boosting'] retrieves the already-trained Section 5 model. We can call .predict_proba() on it at any time — it remembers everything it learned.
🔹 Why F1 uses harmonic mean instead of arithmetic mean
If Precision=0.90 and Recall=0.10:
Arithmetic mean = (0.90+0.10)/2 = 0.50 — looks decent
Harmonic mean (F1) = 2×(0.90×0.10)/(0.90+0.10) = 0.18 — correctly shows it's terrible
The harmonic mean heavily penalizes extreme imbalances between precision and recall, making it a more honest single metric.
🔹 cm.ravel() — What it does
confusion_matrix() returns a 2D array: [[TN, FP], [FN, TP]]
.ravel() flattens 2D to 1D: [TN, FP, FN, TP]
Python tuple unpacking: tn, fp, fn, tp = [850, 115, 127, 317]
Assigns each value to a named variable — much cleaner than cm[0][0], cm[0][1] etc.

🔹 def assign_risk(prob) — Why tiers instead of raw probabilities?
Raw probabilities (0.823, 0.412, 0.156) are meaningless to business teams who don't understand ML. Risk tiers (🔴 High Risk) are immediately actionable — a CRM system can automatically trigger workflows based on them. The .apply() method passes each customer's probability through the function one at a time — like a vectorized for loop.
🔹 df_original.loc[X_test.index, 'Monthly Charge'] — Why reload original CSV?
StandardScaler transformed Monthly Charge into z-scores (-0.23, 1.45) during preprocessing — meaningless for dollar calculations. We use .loc[X_test.index] to retrieve original dollar amounts for exactly the same customers using their original row indices — guaranteeing perfect alignment between churn probabilities and revenue figures.
🔹 .groupby('Risk_Tier')['Monthly_Charge'].agg(Customers='count', Total='sum', Avg='mean')
.agg() applies multiple aggregation functions in ONE operation instead of calling .count(), .sum(), .mean() separately. Each argument names the result column. Efficient and produces a complete financial summary of each risk tier in a single line.
🔹 hasattr(final_model, 'feature_importances_') — Why check this?
Tree models (Gradient Boosting, XGBoost) have .feature_importances_ built-in.
Linear models (Logistic Regression) have .coef_ instead.
hasattr() dynamically checks which attribute exists — making the code robust regardless of which model wins. Without this check, the code would crash if a linear model was selected as final best.
